## 한 줄로 말하면

로컬 파일이 장점인 만큼, **날아가는 것도 내 책임**이다. 클라우드 폴더와 Git을 이중으로 건다.

## 왜 필요한가

노트 시스템은 몇 년 쌓여야 가치가 나온다. 3년 치를 한 번에 잃으면 복구할 방법이 없다.

그리고 백업은 "전부 날아갔을 때"만 쓰는 게 아니다. **버전 이력이 있어야 "어제 지운 그 문단"을 되살릴 수 있다.** 실제로 더 자주 쓰는 건 이쪽이다.

## 설치와 세팅

세 가지 중 하나를 고르되, 클라우드 + Git 병행을 권한다.

| 방식 | 비용 | 장점 | 단점 |
|---|---|---|---|
| Obsidian Sync | 유료 (월 $4~) | 모바일 포함 무설정 | 비용 |
| 클라우드 폴더 (GDrive/OneDrive) | 무료 | 즉시 적용 | 충돌 파일, 이력 없음 |
| Git + GitHub | 무료 | **변경 이력·되돌리기** | 초기 설정 필요 |

Git 방식 세팅 순서다.

1. GitHub 계정 → **Private** 저장소 생성
2. 커뮤니티 플러그인 → **Obsidian Git** 설치
3. 설정 → `Vault backup interval`: `10`분, `Auto pull on startup` ON
4. 볼트 루트에 `.gitignore` 생성

```
.obsidian/workspace.json
.obsidian/workspace-mobile.json
.trash/
```

## 라이브 시연

1. 노트를 수정하고 `Ctrl+P` → `Git: Commit and push` (10분 기다리지 않고 바로)
2. GitHub 웹에서 방금 쓴 문장이 올라온 것을 확인한다
3. **문단을 지우고 저장한 뒤, Git 이력에서 되살린다** — 백업의 필요성을 가장 잘 설득하는 장면이다

## 직접 해보기 (5분)

1. GitHub에서 **Private** 저장소를 만든다
2. Obsidian Git을 설치한다
3. 첫 커밋을 푸시한다

## 흔한 함정

> [!warning] 저장소를 Public으로 만들면 회사 자료가 전 세계에 공개된다
> 생성 화면에서 Private을 고르는 것을 반드시 확인한다. 나중에 비공개로 바꿔도 **이미 색인된 내용은 남는다.**

> [!warning] `workspace.json`을 무시하지 않으면 충돌이 폭발한다
> 이 파일은 창 배치 같은 기기별 상태를 담는다. 기기마다 계속 달라지므로 커밋 대상에서 빼야 한다. `.gitignore`는 선택이 아니라 필수다.

> [!warning] 클라우드 동기화 중에 커밋하지 말 것
> 클라우드 폴더와 Git을 같이 쓸 때, 동기화가 끝나지 않은 상태에서 커밋하면 반쪽짜리 파일이 올라간다. 동기화 완료를 확인하고 커밋한다.

## 마무리

10회차가 끝났다. 정리하면 이렇다.

1. 옵시디언의 본질은 **내 폴더 안의 텍스트 파일** — 그래서 백업·AI·자동화를 마음대로 붙일 수 있다
2. 자동화는 3층으로 쌓인다 — **Linter(서식 정리) → Templater(구조 생성) → Dataview·콜아웃(활용·시각화)**. 문맥 판단은 사람, 서식 처리는 플러그인
3. 수집(Web Clipper) → 정리(Linter/Templater) → 활용(Dataview/AI)이 한 줄로 이어지면, **스크랩만 하던 자료가 실제로 다시 꺼내 쓰이는 자산**이 된다
