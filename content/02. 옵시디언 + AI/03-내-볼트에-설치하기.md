## 한 줄로 말하면

카파시의 원문 아이디어 한 장을 Claude Code에 그대로 던지면, 그 자리에서 raw/wiki 구조를 만들어준다.

## 준비물

- **Claude Code 접근** — 아래 세 경로 중 하나
- **옵시디언 볼트** 하나 (비어 있어도 된다)
- 원문: [Karpathy의 LLM Wiki gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

## 세 가지 경로

같은 Claude Code 에이전트를 어디서 여느냐 차이일 뿐, 아래 프롬프트는 셋 다 똑같이 쓴다.

| 경로 | 여는 법 |
|---|---|
| CLI | 볼트 폴더에서 터미널을 열고 `claude` 실행 |
| VS Code | Claude Code 확장 설치 → 사이드바 채팅 패널 |
| Cowork | 새 프로젝트에서 로컬 폴더 추가 → 이 볼트 폴더를 연결 |

## 직접 해보기 (5분)

1. 위 셋 중 하나로 Claude Code를 켠다
2. 아래 프롬프트를 그대로 붙여넣는다

```
Build me a complete LLM Wiki system based on this idea from Karpathy
(https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f#llm-wiki).
I use Obsidian. Create the folder structure, initial scripts/tools if needed,
and give me clear step-by-step instructions on how to ingest data and have
you maintain the wiki. Make it practical and ready to run today.
```

3. Claude Code가 만들어주는 폴더 구조와 사용법 안내를 그대로 따라간다

## 결과물 확인

프롬프트 한 번으로 매번 똑같은 결과가 나오진 않는다. 실제로 나온 예시 하나는 이런 모양이었다.

```
LLM WIKI/
├── CLAUDE.md          ← AI 지시서 (스키마)
├── README.md          ← 사용 가이드
├── LLM WIKI/           ← 옵시디언 볼트
│   ├── .obsidian/
│   ├── Clippings/      ← 웹 클리핑 저장소
│   └── *.md
├── wiki/               ← AI 관리 영역
│   ├── index.md
│   ├── log.md
│   ├── overview.md
│   ├── entities/
│   ├── concepts/
│   ├── sources/
│   └── analysis/
└── tools/
    └── search.py
```

핵심은 폴더 이름이 아니라 **raw(원본)와 wiki(정리본)가 분리돼 있는가**다. 이름은 매번 다르게 나올 수 있다.

## 흔한 함정

> [!warning] 로컬에 직접 쓴다 — 백업 먼저
> CLI·VS Code는 볼트 파일을 그 자리에서 바로 만들고 고친다. Git이든 뭐든 되돌릴 수단을 먼저 마련해두는 편이 안전하다.

> [!warning] 셋의 결과물이 완전히 같지는 않다
> 프롬프트는 같아도 에이전트가 그때그때 판단해서 구조를 짜는 방식이라, 폴더 이름이나 스크립트 구성이 실행마다 조금씩 다를 수 있다. "정확히 이 구조가 나와야 한다"가 아니라 "raw/wiki가 분리됐는가"만 확인한다.
